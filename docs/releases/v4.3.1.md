# 2026-11-23 — v4.3.1: the agy builder can no longer read credential files

## What's new

This release closes one gap in the agy builder lane. Nothing else changes in how you run Triforge.

- **The agy builder can no longer read credential files.** Since agy 1.5.7, a background agy session starts in Auto mode where the account has it, and from 1.5.14 Auto may read files outside the workspace without asking. agy's read lanes already refused the credential paths (`~/.ssh`, `~/.aws`, `~/.config/gh`, the CLIs' own sign-in folders and the rest of the list the other read-only lanes refuse). The builder lease passed no rules at all. Now it passes `--settings` with the same credential read denies and nothing else, so Auto still approves the builder's edits and safe commands in its worktree. An agy without `--settings` runs as before.

## Details

Live on a Google AI Pro account with agy 1.5.14, the builder command from `_lease_lane_argv` ran from a git worktree. It wrote its file, and its read of a test file under `~/.gemini` was refused by the deny rule (`Permission denied for read_file(...)`). Before the change, the same read was refused only because print mode turned away a confirmation it could not show, a behavior agy does not document. The rule now makes the refusal explicit.

agy's `--mode auto is not available for this account` warning in print mode is logged before print mode signs in. The session then runs in Auto anyway (`SetCycleMode called: auto` in agy's log). D-077 in `ops/decisions/2026-11-23-cli-deprecation-watch.md` records the test.

The rules come from `_agy_lane_settings build` in `scripts/lib/antigravity.sh`, the function that already built the read lanes' settings. The build class keeps the credential denies and the user's own agy rules, and drops the read lanes' read allow and their write and command denies. SELF-29 checks the builder argv: one `--settings` object before `-p`, the credential denies with no allow and no write or command deny, none on an agy without the flag, and the read lanes' settings unchanged.

Upgrading: nothing to do beyond the usual update (`claude plugin update agent-triforge`, or the Codex lines under Update in the README).

v4.3.1 ships without a regenerated probe record: only the agy builder argv changed, and the live run above covers it. The newest record is still `ops/research/2026-11-probe-record.md`.
