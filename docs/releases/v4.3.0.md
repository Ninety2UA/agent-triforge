# 2026-11-23 — v4.3.0: review covers what ships, a 2.1.325 worker floor, unattended runs that rule and continue, current models

## What's new

This release brings Triforge up to date with Claude Code 2.1.330, Codex 0.171.0, agy 1.5.14 and Cursor 2026.11.22, closes a path where code changed after review could ship unreviewed, and tightens what every builder is told.

- **The last review covers what ships.** In `at-ship` and `at-coordinate`, Phase 5 could fix code after the review had converged and then finish the sprint. Now any code or test change made after the converged review gets a delta review from a roster member that wrote none of it, before completion, counted against the three-cycle cap. Test files get no exemption: a rewritten assertion changes what a green suite proves. In `at-test`'s fix cycle, production-code fixes go through a lease with a pinned reviewer. The completion checklist and `coordinate.sh`'s copy of it carry the new item.
- **A claude worker needs Claude Code 2.1.325.** 2.1.323 stopped Write and Edit from writing into a path a `Read` deny rule covers, which is how the worker lane denies credential paths, and stopped `-p` from running Bash unsandboxed when a `--settings` file fails validation. 2.1.319 to 2.1.325 carry more sandbox fixes. Below the floor a worker refuses to start and session start prints a `worker-floor` line. The lead's own floor stays 2.1.277.
- **Unattended runs rule and continue.** The prompt `coordinate.sh` sends each session now says no user is answering: the lead rules on reversible questions inside the approved goal and records each one as a `Ruling:` line in `ops/CHANGELOG.md`, the ledger `at-wrap` exports, while a missing approval, a spent review cap or another hard stop still stops the work that depends on it and is recorded as a `Stop:` line. Phase 1.1 of `at-ship`, `at-coordinate` and `at-plan` says the same. The prompt also names roles from `ops/roster.toml` instead of fixed CLIs, so a roster override reaches every phase.
- **Three more lines in every builder's dispatch contract.** Check your work with the commands the project already declares, and do not install a package only to verify. Never discard work in the worktree (`git reset --hard`, `git stash`, `git clean`, `git restore`, `git checkout -- <path>`); a refused step stops only what depends on it. Never signal a process you did not start.
- **Reviewers see new files.** The review package listed untracked files by name only, so a lane that reviews from a copy of HEAD could not read a test the tester had just written. Every untracked regular file outside `ops/` and dot directories, up to 256 KiB, now joins the package diff as a new file; the lead's `ops/` records, the per-CLI files the bootstrap writes under dot directories, file names that mark a secret (`credentials`, SSH keys, `.pem`, `.env` and the like), files holding a private key block or a key shape the lanes already redact, larger files and symlinks stay listed by name. The Phase 5 trigger lists changes with rename detection off, so a file moved into `ops/archive/` still counts; it counts an untracked file only when it is new, changed or gone since the review converged, against a list of digests saved as Phase 5 starts and kept across resumed sessions. Two helpers in `scripts/lib/gates.sh`, `delta_untracked_save` and `delta_review_paths`, do both steps; and a snapshot git cannot resolve sends the delta review back to the sprint's build base.
- **Prompts reach a lease as file content.** The skills now show writing a dispatch prompt to a temporary file and passing `"$(cat "$PF")"`, never splicing task rows, findings or fetched comments into a quoted shell string, where a backtick would run in the lead's shell.
- **One trigger for knowledge capture.** Callers applied `knowledge-compounding` only after "more than 30 minutes" or a "non-trivial" fix, criteria the skill itself rejects. Now they apply it whenever the work corrected a wrong belief (a failed first approach, a P1 or P2 a reviewer caught, a wrong assumption or document), and the skill alone decides whether anything is written.
- **Three evidence rows for claims.** `verification-before-completion` gains rows for "a gate is enforced" (run it against a deliberate violation), "a forced edit landed" (the diff shows it) and "a prompt, skill or lane change works" (one live run, or the claim is written `not run`).
- **Newest models by default.** The `fable` alias is Fable 5.2 from Claude Code 2.1.321, and the docs say so. Codex runs `gpt-6.2-astra` (Codex 0.166.0 or later). agy runs Gemini 4 Neon (High); on an account whose `agy models` lacks it (Neon needs a paid Google AI plan), each agy call runs the next Gemini 4 model the account lists (Hydrogen, then Argon), else Gemini 3.8 Flash, at the same level, and says so. The default stays at (High); choosing `xhigh` or `max` effort in setup selects Neon's (XHigh). Devin runs `swe-2-flash-medium`, the newest model on Devin's free plan.
- **Codex trust, stated as it is.** From Codex 0.169.0 an untrusted project keeps project config, project hooks and project MCP servers off, even with `--dangerously-bypass-hook-trust`, and a runtime `-c` trust override is ignored. A first `codex exec -s workspace-write` run no longer writes the trust entry, so setup no longer says it does. Triforge ships no project hooks, so a project with no trust entry skips only its Codex memory setting; one you explicitly mark `untrusted` also skips the root `AGENTS.md`, so neither a Codex lead nor a Codex worker sees Triforge's pointer block. Adding the trust entry stays your call.

## Details

### Why review must cover Phase 5

Three outside projects that ship agent workflows (tstack, gstack and pstack) each concluded that a verdict covers a patch, not a branch: a review that converged before a fix says nothing about the fix. Triforge's own rule is that every implementation task merges only after a non-author cross-review, and Phase 5 was the one path that skipped it. The delta review uses the at-review dispatch with `REVIEW_BASE` set to the commit the converged cycle reviewed. Binding a review receipt to the reviewed tree, so a merge can prove it, is planned separately.

### Security fixes to be on

These are recorded apart from the floors, because no lane depends on the fixed behavior:

- agy 1.5.14. 1.5.3 to 1.5.14 fix six security issues, among them MCP custom headers sent to another host on a redirect (1.5.9). From 1.5.7 a headless session with no saved mode starts in Auto where the account has it, and from 1.5.14 Auto reads files outside the workspace without asking. The agy builder lane passes no `--settings`, so on such an account an agy builder can read files the read lanes deny. This release does not change the lane: on the probe host Auto is not available and a bare headless run could not write even inside its workspace, so a change could not be tested.
- Cursor 2026.11.17 stops exposing the access token or API key in the process list.

### The probe on this host

A full probe of the v4.2.0 tree ran on 2026-11-22 (171 rows). Every Codex row that runs a shell command failed with "gRPC code-mode host timed out waiting for session opening response". Codex 0.171 runs shell commands through a helper binary, and on the probe host that helper was waiting on a macOS launch check for its quarantined download, so it never started. That is a host condition, not a lane regression; the 4.2.0 record passed the same rows on 0.166.0. After a Homebrew update of Codex on an unattended Mac, clear the launch check for `codex-code-mode-host` and `codex-exec-server` as well as `codex`. CC-02 failed because the account had reached its Fable usage limit, so the ladder ran Opus, the safe direction.

### Smaller fixes

- `best-practices-researcher` gets 150 turns and `framework-docs-researcher` 80 (both were 40). The first repo-mining swarm of this cycle lost all ten reports at 41 turns; at 100 three workers used 100 to 107.
- CDX-04 records Codex 0.169's untrusted-project behavior as INFO with the reason instead of a bare FAIL.
- Contradictions between skills fixed: `at-resume` on how persona spawns get their model, a "never escalate" warning that contradicted the same skill's own escalations, stale step references, a persona's report heading the synthesizer would reject, review-lane lists that left out optional lanes, and personas that named Claude or Codex as the fixer.
- `best-practices-researcher` treats fetched content as untrusted data, like the other web personas.

Upgrading: refresh the marketplace, then update (`claude plugin marketplace update agent-triforge`, then `claude plugin update agent-triforge`; the Codex lines are in the README's FAQ), then check the following:

- Run `claude --version`. Below 2.1.325 a claude worker refuses to start, and the shipped builder is a claude worker. Session start prints `worker-floor` until you run `claude update`.
- Under a Codex lead, approve the hooks again. Any change to the plugin's contents, this update included, asks for approval again.
- If a script reads the prompt `coordinate.sh` builds, the phase lines now name roles, and a new paragraph says no user is answering.
- Run `codex --version`. The shipped Codex pin, `gpt-6.2-astra`, needs Codex 0.166.0 or later; on an older Codex, update it or set the reviewer and tester `model` to `gpt-6-astra` in `ops/roster.toml`.
- Your project's `ops/roster.toml` keeps the models it was set up with. Session start prints a drift line for each role whose pin differs from the new defaults; run `at-setup roles` and pick "restore shipped defaults" to take them.
- If you use Codex workers in a project you have not trusted, add the trust entry `at-setup` prints, or accept that the project's Codex memory setting is skipped.
