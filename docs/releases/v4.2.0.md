# 2026-11-05 — v4.2.0: today's CLIs read correctly, a Coverage line in every review lane, fail-closed verdicts, a 2.1.314 worker floor

## What's new

This release brings Triforge's detection, notices, docs and probe up to date with Claude Code 2.1.318, Codex 0.166.0, agy 1.5.1 and Cursor 2026.11.05, and closes gaps in how the review cycle decides it is done.

- **Claude Code's `instructionFiles` setting is read.** Whether a `CLAUDE.md` hides `AGENTS.md` depends on that user-tier setting. Setup and session start now read it and report what Claude Code loads under its mode, instead of assuming the default.
- **Codex's content-bound hook approval is read.** Codex now ties a plugin hook's approval to the plugin's contents. Detection, setup and the probe read the new shape and the older one. Any change to the plugin's contents, this update included, asks for approval again, and until then a Codex lead runs without the plugin's hooks.
- **An agy run that stopped early no longer passes as finished.** Any `finished_reason` marks the run incomplete, a print-timeout expiry is a timeout that is not retried, and every nonzero exit writes the status file the promotion guards read. Partial output or an error message no longer lands as a review or an architecture report, and a cut-off lease never goes to review.
- **The default review no longer stops at agy's analyst.** On agy 1.5.1 a tool call that needs a permission prompt ends a headless turn with an empty response, so one attempted write, command or read outside the workspace lost the analyst and stopped the whole review. 4.1.1 fails the same way. The Antigravity analyst now returns its review instead of trying to write it, and a refused tool call no longer loses the run.
- **Every review lane ends with a Coverage line.** It reads `Coverage: complete`, `Coverage: partial: <reason>` or `Coverage: none: <reason>`. A lane that reports less than complete, or omits the line, is a gap the cycle cannot converge on. Coverage is self-reported: the snapshot-bound review receipt is the first 4.3 item.
- **Reviewers judge every `Accept:`.** An unmet one is at least P2, and one they cannot run is judged by reading and listed `not run`. They read callers, contracts and surrounding code before reporting or clearing a finding, and never quote a secret value. Convergence needs a report on the final changed snapshot: a cycle that applied a P1 or P2 fix re-reviews the changed files, and that review counts against the three-cycle cap.
- **Plan and verify verdicts fail closed.** A new helper, `persona_verdict`, reads `plan-checker` and `integration-verifier` reports. It passes only an explicit APPROVED with no blocking issue, or an explicit PASS with a matching recommendation. Anything else, a malformed report included, stops the plan or the wave.
- **`coordinate.sh` exits 75 when the sprint did not converge.** It now exits 75 instead of 0 when its sessions run out without `ops/.sprint-complete`, so exit 0 means the sprint completed or a dry run printed. A wrapper that treats any nonzero exit as a crash needs to handle 75 as "run again to continue".
- **A claude worker needs Claude Code 2.1.314.** That build carries the sandbox isolation fixes. Below it a worker refuses to start and session start prints a `worker-floor` line. The lead's own floor stays 2.1.277.
- **Codex workers no longer load your installed Codex plugins.** Foreground, lease and persona workers run with `--disable plugins`. A Codex lead keeps its own trusted plugin hooks, and skills under `.agents/skills/` still load.
- **Cursor's default moved to Grok 4.7.** The shipped pin is `grok-4.7-xhigh`, and it answered live on Cursor 2026.11.05. A roster that pins the 4.6 id keeps working.
- **The probe reports what it proved.** Rows that depend on a host setting pin it and report the host's value. On an OpenCode V2 host every OpenCode row reads `UNAVAILABLE` and says why, and a deny row needs a positive control before a missing marker counts. A local row installs the exported tree under both leads, and a new row proves the Codex worker flag.

## Details

### Instruction files

The setting is `pluginConfigs."cc-plugin-agents-md@builtin".options.instructionFiles` in your user-tier `settings.json`. A live run of each mode on Claude Code 2.1.318 showed:

| Mode | No `CLAUDE.md` | A plain `CLAUDE.md` | A `CLAUDE.md` with `@AGENTS.md` |
|---|---|---|---|
| `claude-md-or-agents-md` (default) | loaded | hidden | loaded |
| `claude-md-and-agents-md` | loaded | loaded | loaded |
| `claude-md` | hidden | hidden | loaded |
| `managed-only` | hidden | hidden | hidden |

Triforge reads the user tier only, and never writes it. Managed settings and an active `--settings` are not read, and the verdict's reason says so. A value that is unset, unknown or unreadable gets the default's verdict, with the reason named. `claude-md` and `managed-only` print one warning naming the setting, with no import offered. An import that already loads under `claude-md` reads as visible. With an import under `claude-md-and-agents-md`, input tokens matched the default mode in each of three runs, so the file is read once.

### Codex hook approval

`hooks/list` adds no new field. A plugin hook's `currentHash` is one string, `sha256:<declaration>/sha256:<content>`, and a project hook's has no slash. In `hooks.state`, a plugin hook's `trusted_hash` holds the declaration half and `trusted_content_hash` the content half. A project hook keeps `trusted_hash` equal to `currentHash`. Detection accepts that shape and a carried-over approval with only the declaration half, which Codex 0.166.0 also reports as trusted and runs. For a carried-over approval the content binding is Codex's own: its first `hooks/list` records a baseline in `$CODEX_HOME/.hook-trust/`, so a first listing after an update pins the updated contents. Your `config.toml` stays byte-identical. Upstream calls the value opaque, so if the format changes, detection reads the hooks as absent and the probe row fails.

### agy

The analyst lane was found failing live on agy 1.5.1, 5 runs of 5, and on 4.1.1, 2 of 2. `invoke_antigravity` now passes session-only rules through `--settings` where agy has that flag (no write, no command, reads everywhere except the credential paths; nothing saved, your own rules kept), and all four Antigravity agents are read-only and return their answer. The analyst, research and documentation agents no longer run shell commands. After the fix the lane promoted a review in 12 runs of 12 on 1.5.1, native and injected, and two runs with a seeded defect both reported it. Not run live: `--settings` beside real user-tier rules, and an agy older than 1.5.1.

Observed live on agy 1.5.0, before the host updated itself to 1.5.1: a normal finish is exit 0 with no `finished_reason`; an expiry is exit 3 with `finished_reason: print_timeout`; an interrupt is exit 1 with `interrupted`; a bad model is exit 1 with `error`. With `--print-timeout` equal to Triforge's outer window the outer `timeout` usually wins, so the usual route is exit 124. Both are class timeout and neither retries. A lease that expires follows the existing orphan path: requeued once, then escalated, never reviewed.

These stay fixture-only, because they could not be provoked on 1.5.0: a `finished_reason` at exit 0 (the shape comes from agy 1.4.11's release note), an `AGY_ERROR` with no stderr line or with an empty body, and `retryable: true` on an expiry. The lease lane's expiry ran on stubs; only `invoke_antigravity` ran on real agy.

### Review

The Coverage line must be the last non-empty line, outside any code fence, so a line quoted from a diff cannot speak for the lane. A model that wraps its whole report in a fence therefore reads as missing, and a re-run clears it. Under Codex's verdict schema the field is `coverage`, and `ops/REVIEW_CODEX.md` now holds the JSON answer plus the folded line, not the session's text. Agent files already deployed in a project are not rewritten; the prompts carry the rule, so those lanes still report it.

Three limits stay. Coverage is self-reported: a lane can claim complete falsely, and only the quoting and contradiction paths are closed. `at-build`'s team mode and `team-lead` run their own reviews, and no gate reads the Coverage line there. The re-review rule is prose, not machinery: a lead that proceeds on an earlier cycle's report is not caught by anything. The snapshot-bound receipt in 4.3 is what would close these. For the same reason, `lease_merge`'s wording changed: the pin names the reviewer and records that the review step was reached, and does not prove the final snapshot was reviewed.

`persona_verdict` is enforced by `at-plan`'s wait block, which exits on it. `at-ship`, `at-coordinate` and `at-build` tell the lead to read the verdict through it. `findings-synthesizer` treats the dispatched lane list as authoritative, and dispositions say Cycle N everywhere.

### Codex workers

`--disable plugins` is proven for hooks and skills, not for plugin MCP servers, which were not tested. The flag needs no higher floor: it exists and works on 0.153.0. `-c plugins._default.enabled=false` does not stop a plugin, so it isn't used. Project hooks and skills provisioned under `.agents/skills/` still load in a worker.

### Smaller fixes

- `best-practices-researcher` and `framework-docs-researcher` get 40 turns (was 12), which makes their default timeout 8000 s. A persona that spends its turn budget now returns rc 81 with a line naming the fix.
- The key scrubber no longer redacts words like `Task-completion`.
- A blank line inside an `[R]` task no longer ends the task in the review package.
- `at-resolve-pr` paginates every comment fetch. A live pull request with 42 review comments returned 30 without the flag.
- `learnings-researcher` is skipped when the project's solutions, decisions, `MEMORY` and `CHANGELOG` hold nothing beyond the skeleton.
- `plan-checker` no longer offers an "approve with caveats" exit or a "costly" reversibility value.
- `locate-triforge.sh --help` prints usage and exits 0 before resolving anything.
- `validate-versions.sh` gains a local link and anchor check.
- Kimi's install hints use the global `code.kimi.ai` address.

Upgrading: refresh the marketplace, then update (`claude plugin marketplace update agent-triforge`, then `claude plugin update agent-triforge`; the Codex lines are in the README's FAQ), then check these.

- Run `claude --version`. Below 2.1.314 a claude worker refuses to start, and the shipped builder is a claude worker. Session start prints `worker-floor` until you run `claude update`. `TRIFORGE_CLAUDE_SANDBOX=off` still runs the lane without the sandbox.
- Under a Codex lead, approve the hooks again. Any change to the plugin's contents, this update included, asks for approval again, and until then a Codex lead runs without the plugin's hooks. Pick "Review hooks" when Codex asks, or open `/hooks` in the session.
- A user-tier `command(...)` allow rule no longer reaches the read-only agy lanes: their session rules deny commands, and a deny wins.
- If a script wraps `coordinate.sh`, handle exit 75.
- If a script reads `lease_merge`'s no-pin refusal or `ops/REVIEW_CODEX.md`, re-check it. The refusal's wording changed, with the same exit code and state.
- If your roster pins `cursor-grok-4.6-xhigh` it keeps working. Change it to move to Grok 4.7.
