# 2026-10-13 — v4.1.1: the README in agent-blueprint's order, light diagrams, release notes per version

## What's new

This release changes the documentation and the release tooling. Nothing changes in how you run Triforge.

- **The README follows agent-blueprint's order.** It starts with what Triforge is, then covers install for either lead, getting started, unattended runs, upgrading from 3.x and updating, and ends with the reference sections. It shows only the latest What's new; older releases are in the collapsed [Release history](../../README.md#recent-changes).
- **The diagrams are light.** The 13 dark diagrams became 15 light ones that read on GitHub's light and dark themes, and on a phone a tap opens each one full size. Two are new: the install routes and the unattended-run loop. Checking every label against the code corrected a few stale facts: there are five quality gates, at-ship reviews in five lanes, the kill grace is 10 s, and test fix cycles stop at 3.
- **Each release has its own notes file.** A version's notes live in `docs/releases/v<version>.md`, and the release workflow publishes that file as the GitHub release.
- **The maintainer gates are stricter.** `validate-versions.sh` fails a version bump that has no notes file and rejects Liquid delimiters under `docs/`, which break the GitHub Pages build. It also fails when a diagram source changed without a re-render, or when a diagram names a stale pin, a wrong count or a Codex invocation without its `agent-triforge:` prefix.

## Details

The README work kept every heading that other files cite, so their links still resolve, and the `#whats-new` and `#recent-changes` anchors still land where they did. The ten dark SVGs that nothing embedded any more are gone. The website keeps its own four SVGs until its redesign. The README also drops its comparison with Agent Blueprint, and the maintainer-only watch commands are no longer in the published repository.

The diagrams come from `docs/images/render-diagrams.html`, plus three Excalidraw sources in `docs/images/excalidraw/` that the page embeds. `node docs/images/render-diagrams.js` renders each one at 2x and writes `docs/images/render-diagrams.sha256`. It refuses to render when Inter or JetBrains Mono did not load, so no PNG ships in a fallback font.

`scripts/release-notes.sh` takes the release title and body from the notes file and turns its `../../` links into links at the release tag. It exits 1 when the file is missing, has no `v<version>:` heading, or has nothing after the heading. In `scripts/validate-versions.sh`, check 1 now requires the notes file and every line of the README's What's new block in it. Check 12 covers Liquid delimiters, and check 13 the render stamp. The README checks skip only the `## Release history` section, so FAQ, Contributing and License are checked again.

Upgrading: nothing to do beyond the usual update (`claude plugin update agent-triforge`, or the Codex lines under Update in the README).

v4.1.1 ships without a regenerated probe record, as v4.1.0 did: no adapter, model pin or runtime path changed. The newest record is still [`ops/research/2026-09-probe-record.md`](../../ops/research/2026-09-probe-record.md).
