# Resuming with an open lease ledger

`ops/leases.toml` is the lead's ledger: single-writer, lead-owned. When it exists at resume, wave state is reconstructed from it, never from memory.

- `lease_heartbeat_check` first. Builders run detached, so they outlive the lead that dispatched them: it adopts a builder that still runs (pid, pgid and start time match) and collects one that finished while no lead was watching, both with `reason=lead-exit` and the requeue budget untouched; it reclaims orphaned leases (a builder that died without an exit record) and runs the git-integrity comparison every lease helper runs: `.git/config`, `.git/hooks/`, `.git/info/`, the global and the lead's trusted git config, the ledger, the default branch and each open lease's pointer files against the `[baseline]` in the ledger. rc 44 (`_RC_LEASE_INTEGRITY`) means something changed that the lead did not change: the open leases are escalated and the surface is named. Inspect it (a saved copy sits at `<lease root>/lead/<name>.changed-<UTC time>`); when you or the user made the change, `lease_rebaseline [task...]` accepts it and resumes the escalated leases. rc 80 means a building row has no pid or output file to judge liveness by: inspect it and reclaim it by hand.
- Open leases by state: `leased` leases are dispatched or requeued (`lease_requeue`, which prepends the forced-reflection questions); `review` leases keep their pinned reviewer (`lease_pin_reviewer` is already recorded; the same reviewer stays across all ≤ 3 fix cycles); `orphaned` leases were reclaimed by the heartbeat check and are requeued. `building` leases are waited on with `lease_wait` in bounded slices until none is building, each call inside the lead's tool limit (the harness reference says how). Each repeat call names only the leases on the last `still building:` line, or names none to watch every building lease. rc 75: the budget ran out with builders still running, so call it again. rc 80: a building row it cannot verify, which ends the loop; stop and read the message. rc 44: an integrity escalation, handled as above.
- `merged` leases are already one squash commit each on the sprint integration branch. Never redo them, and never re-dispatch their tasks.
- `lease_status` prints the counts and the per-lease rows for the summary.
- Create, merge and promotion refuse when the checkout is no longer on the integration branch the lead recorded, and merge and promotion when that branch moved since the lead's last merge — a resume that finds the checkout elsewhere switches back before any lease call.
- The session-start hook reports an active ledger ("N active lease(s) from a previous session") and points at `lease_heartbeat_check`; it never deletes worktrees.
