# Under a Claude Code lead

- Invoke as `/at-build`. Claude Code exports `CLAUDE_PLUGIN_ROOT`, which the locator accepts first when it passes the Triforge-root test.
- Personas (`integration-verifier`, and `continuous-reviewer` in team mode) run through `dispatch_persona` in the Bash tool, not the Agent tool; one that fails or writes nothing is a failed sub-task rather than a dropped scope.
- Agent-team mode is Claude agent teams (`lead_field lead.agent_teams` is true for this lead; it needs the agent-teams environment flag that `settings.json` ships). It is the one Agent-tool spawn left: a general-purpose teammate whose prompt is the `team-lead` persona's text (`persona_prompt team-lead` prints it) plus the wave plan, at the top tier (`fable` at `max` when the newest probe record's row CC-02 shows Fable PASS, else `opus` at `max`) with the manifest's turn budget. Its tools are unenforced: the Agent tool does not narrow a general-purpose teammate, so the team-lead's confinement is the lease protocol it drives, not a tool list. One spawn round, no spawn-of-spawn; wait for it before merging.
- `lease_wait` runs in the Bash tool: pass `timeout: 600000` (the registry's `wait_budget_s` 600 s × 1000), never `run_in_background`; its own budget defaults to 585 s, so it returns inside that limit. A `claude -p` lead that ends its turn leaves its builders running; the next session's `lease_heartbeat_check` picks them up.
- The never-downgrade trio (`plan-checker`, `security-sentinel`, `findings-synthesizer`) is pinned to the top Claude tier in its manifest entries, so no spawn here restates it; narrow builder tasks may step down the ladder that `triforge_ladder` prints.
