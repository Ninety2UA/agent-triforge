# Gated learnings-researcher (C4)

Pay for the `learnings-researcher` persona only when `ops/solutions/` plausibly knows the changed modules. The gate runs inside the dispatch block (the dispatch reference), ahead of the lanes, with no model call: it derives module names from the changed paths (the full path, the basename, the stem and the parent directory, skipping names under four characters) and greps `ops/solutions/` for them. The changed paths come from the review package's inventory (`$REVIEW_PKG/inventory.txt`, rename sources and untracked files included), so the gate runs no git. The matched entries land in `$REVIEW_RUN/learnings-matches.txt`, and the block prints them, or "learnings-researcher skipped" when there are none.

On a match the persona starts in the same background round as the review lanes, outside the lane list. Its input is the changed paths and the matched entries (data), its task the `--brief`, which names the package's full diff, and its report `$REVIEW_RUN/learnings.md`, outside `ops/REVIEW_*` because it is context, not a review lane. The block waits for it with the other lanes; a failure prints a note and the review goes on, since synthesis then runs without known-issue context and the report says so. Synthesis hands the report to `findings-synthesizer` as **known-issue context**. When the gate prints "skipped", nothing is dispatched.

## The planning gate

The planning spawns (`at-plan`, `at-ship`, `at-coordinate` and the `at-deep-research` swarm) have only goal text, so they have no changed paths to grep. They ask one question with no model call, `learnings_store_empty`: do `ops/solutions/` and `ops/decisions/` hold no file, and are `ops/MEMORY.md` and `ops/CHANGELOG.md` absent or byte-identical to their templates? When they do and are, the spawn prints "learnings-researcher skipped: the store holds only the skeleton". A store it cannot prove empty, a template this install lacks included, runs the persona. The review gate above does not use it.
