## 1. Executive summary

The May and July gaps are closed; this cycle is dominated by **model-generation moves on all six lanes** and by **discovery/permission mechanics that changed under Triforge's feet** — several of which reverse July probe rows (both directions).

1. **Model catalogs moved on every lane — Triforge's shipped pins are one generation stale on all six.** Claude **Fable 5.1** (`claude-fable-5-1`, GA 2026-09-01; the `fable` alias resolves to it from Claude Code 2.1.257) and **Opus 5** (`claude-opus-5`, 2026-07-24; the `opus` alias now means Opus 5, not 4.8). Codex **`gpt-6-astra`** (flagship and bundled default since 0.153.4; efforts low…xhigh, max, ultra; lead-probed READY at `xhigh` on 0.154.0). **Gemini 3.8 Flash** (GA 2026-09-02, `agy` default `Gemini 3.8 Flash (Medium)`; **no Pro newer than 3.1 Pro exists** — 3.1 Pro is still preview-only and 3.5 Pro is "coming soon"). OpenRouter **`z-ai/glm-5.3`** (2026-08-18, preloaded) plus the `~z-ai/glm-latest` alias. Kimi's managed alias is **`kimi-code/k3`** — the shipped `kimi-k3` pin is an open-platform ID that fails on OAuth hosts. Cursor **`grok-4.6`** (2026-08-12; effort via bracket syntax `grok-4.6[effort=xhigh]`; lead probe CUR-05 PASS). Per the user's standing direction this cycle ("update the models to the latest — Fable 5.1, GPT Astra, Gemini 3.8 Flash"), all six pins move (ADR D-020..D-025).
2. **`.agents/skills/` is the cross-CLI skills path for five of six CLIs — and Claude Code is the exception** (fixture test §3.1: agy [when the workspace is bound], Codex, OpenCode, Cursor, and Kimi [per docs] all read it; Claude Code reports "Unknown command"). Triforge's session-start copy is the right mechanism, but it is **copy-once** — plugin updates leave user projects on stale skills for five CLIs (repo-watch N1).
3. **Slash commands are per-harness, not portable**: Claude Code (`.claude/commands` ≡ skills), OpenCode (`.opencode/command(s)/` via `opencode run --command`, native, verified), Cursor (`.cursor/commands/` + `/name` in `-p`, verified), agy (skills *are* the slash commands; `agy -p "/<skill>"` expands headless since 1.1.9 — verified), Codex (custom prompts **deprecated**, `~/.codex/prompts/` only, **not expanded under `codex exec`** — verified: the model searched the repo and found the file by luck), Kimi (`/skill:<name>`; headless expansion undocumented).
4. **agy project-tier hooks DO fire headless — July AGY-08 was a probe-shape error.** With the documented `.agents/hooks.json` named-hook shape and event names (PreInvocation/PostInvocation/PreToolUse/PostToolUse/Stop) all five events fired under `agy --add-dir … -p` (lead marker-file re-probe, 2026-09-11). The harness still writes the old settings.json-style file with `SessionStart/AfterAgent/AfterTool` and records FAIL — harness fix scheduled (D-028). Deny-vs-skip-permissions (AGY-09) and `--sandbox` (AGY-10) remain FAIL and the adapter posture (never pass the skip flag; confine via lease worktree) stands.
5. **agy plugin agents are still not surfaced (AGY-12 FAIL) — root cause found:** agy 1.1.6+ discovers Markdown agents carrying `mainAgent`/`subagent`/`commandExecutionPolicy` frontmatter (the discovered Flutter plugin agent has exactly that); Triforge's four `antigravity-agents/agents/*.md` still use `tools`/`max_turns`/`timeout_mins` with **Gemini-CLI tool names that agy does not have** (`read_file`, `write_file`, `glob`, `list_directory`, `run_shell_command` — only `grep_search` exists; the spec warns unmapped names "may cause the subagent process to hang"). Migration is a concrete /lfg item (D-027).
6. **Codex: `--full-auto` is REMOVED (0.147.0), not deprecated; project trust now gates `.codex/hooks.json`, `.codex/config.toml`, `.rules` (0.147.0) and project `AGENTS.md` (0.150.0) under `codex exec`, with unset trust = untrusted and no exec-mode prompt.** The harness CDX-04 still PASSES on 0.154.0 (hooks fired in an untrusted fixture with `--dangerously-bypass-hook-trust`), so the bypass flag still carries automation — but a trust entry `[projects."<abs>"] trust_level = "trusted"` is the durable path and lease worktrees inherit root trust. Also: `.codex/agents/*.toml` is now swept as standalone role files, so Triforge's `agents.toml` triggers a non-fatal "Ignoring malformed agent role definition" warning (D-026); `include_plan_tool` was never a Codex key (real switch `tools.update_plan.enabled`, default false since 0.152.0); `max_depth` is V1-only and ignored by the V2 models Triforge pins; `multi_agent_v2` graduated to `stable` (still default false; #31097 still open).
7. **Kimi 0.42.0 reverses KIMI-03:** `--agent <name>` / `--agent-file <path>` work in `-p` (probe PASS). `--skills-dir` is now counterproductive (it *replaces* auto-discovered dirs, and `.agents/skills/` is native). The shipped project `.kimi-code/config.toml` is **not read at all** (only the user file is) — its telemetry, default_model and deny rules are inert; headless runs as "Never Ask" with no dangerous-command guard (0.41.0). Auth is still AUTH-FAIL on this host (`kimi login` is a user action).
8. **Claude Code: `effort:` frontmatter was silently ignored on Opus 4.7/4.8/Fable 5 until 2.1.267 (2026-09-09)** — Triforge's shipped `effort: max/xhigh` only took effect from that build (floor → ≥ 2.1.267). Task/Todo tools are OFF on every current model unless `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` (agent-teams shared task list silently unavailable); `--bare` "will become the default for `-p` in a future release" (skips hooks, skills, commands, plugins, MCP, CLAUDE.md); hook stdout that looks like JSON but isn't is now a hook error (2.1.246); `PermissionRequest` hooks fire in `--print` (2.1.268); `defaultMode: bypassPermissions` in project settings is ignored (2.1.257); symlinked plugin component paths are refused (2.1.257 — Triforge copies, so unaffected).
9. **OpenCode: no breaking change on the dispatch surface** (flag set byte-identical 1.18.3 → 1.18.30). Docs and source say an explicit `deny` survives `--auto`; the harness OC-06 negative still shows the denied command executing on 1.18.30 and two lead re-probes hung — **kept as an open watch; the adapter stays off `--auto`**. New: `OPENCODE_PERMISSION` env var injects an inline permission config per dispatch; `run` answers subagent permission asks (1.18.20); unknown top-level config keys are ignored (1.18.16); a V2 config/CLI is in development (forward risk). OpenRouter was connected on this host, so OC-02/04/05 flipped FAIL → PASS.
10. **Cursor: the binary is now `agent` (primary) with `cursor-agent` as a legacy symlink**; skills load from `.agents/skills/`, `.cursor/skills/`, `.claude/skills/`, `.codex/skills/` (all four verified); subagent frontmatter has **no `tools` field** (Triforge's `readonly: false` is the documented field); still no `--agent` selector; headless hooks still silent (CUR-06 FAIL); `--sandbox` still non-confining (CUR-07 FAIL); `--mode plan` still read-only (CUR-08 PASS).
11. **`/goal` hard-gating is flaky headless** — CC-03 flipped PASS → FAIL in the harness; two lead re-runs went PASS then FAIL (1/3 this cycle). The `ops/.sprint-complete` sentinel remains the authoritative completion mechanism; `/goal` is a best-effort assist (DOCUMENT, D-030).
12. **Registry drift:** the agy `docs` URL serves the installer script and the `changelog` URL redirects; Kimi's `docs` URL is still an SPA shell (July candidate #3 unapplied); the agy "sparse release notes" note is stale (notes are now detailed).
